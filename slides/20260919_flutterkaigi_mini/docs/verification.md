# 描画・動作確認

確認日: 2026-09-14（JST）

## 今回の変更

初版へのフィードバックに合わせ、剛体パーツの回転を16関節のスキニングへ置き換えた。
提供された三面図、8方向の3Dモデリング画像、ぬいぐるみ写真を再確認し、
WebのFlutterScene描画を正面・横・背面・斜めから比較した。

- 羽根の外向きの傾きを除き、身体の側面に沿う向きへ修正。
- 羽根の両面の縁・球の極などの重複頂点を結合し、法線を共有。
  羽根・足・黒い輪郭の分割も増やした。115,028三角形、26メッシュ。
- 羽根の上端を胴体に重み付けし、肩・中間・羽先の3関節で曲がりを分散。
  バイバイでは翼面を正面へ向け、身体を傾けながら先端を遅れてしならせる。
- 脚を連続したスキンにし、膝・足首のIKで接地と振り出しを制御。
  短い脚はわずかな伸縮を許し、胴体にも呼吸・傾き・上下動を加えた。
- 歩行は周期ごとの減速を除去。ジャンプは予備動作・複数回の羽ばたき・着地へ変更。
- 待機を追加し、起動時の動作に設定。切り替えは0.3秒で補間。
- 均一な環境光をスタジオ環境光へ変更し、羽根・足の曲率を見やすくした。
  下向きの白い胸が暗くなりすぎないよう、前方下から弱い補助光を追加。

参考画像・確認画像はGit管理対象から外している。作成したGLBと生成ソースを管理する。
比較画像はローカルの `docs/screenshots/soft-*.png` に保存。

## 実行環境と確認範囲

- Flutter 3.47.1 / Dart 3.13.1 / flutter_scene 0.23.0。
- Webリリースビルドをローカルブラウザで操作。FlutterScene内蔵WebGL2で描画。
- 実際の `assets/models/dashmaru.glb` をビルドフックで変換し、`loadScene` でロード。
- macOSデバッグビルドとモデル変換は成功。今回の改良版のネイティブ画面操作は、
  Macがロックされていたため未実施。初版のネイティブ確認とは区別する。

| 動き | Webで確認したこと |
| --- | --- |
| 歩く | 側面で膝・足首が曲がり、左右の足が交互に上がる。支持脚は接地。周回時も歩き続ける |
| ジャンプ | 予備動作から離床し、両翼が上下に羽ばたく。着地で脚と胴体が縮む |
| 手を振る | 付け根を保って翼が上がり、羽先の形と向きが変化。胴体も傾く |
| まばたき | 両目の開閉。完全閉眼時には黒いまぶたの弧が残る |
| 待機 | 呼吸と頭・身体・羽根の小さな揺れ。足は接地したまま |

閉眼の再現用URL: `?motion=Blink&time=0.748&camera=front`。
手振りの形状確認用URL: `?motion=Wave&time=1.3&camera=front`。
ライブ再生に加え、固定時刻で付け根・表情を確認した。
動作切り替え、再生・一時停止、正面・横・背面のカメラ操作も確認した。

## モデルの機械検証

`python3 tool/check_dashmaru.py`:

- 26メッシュ、115,028三角形、639アクセサの範囲・有限値。
- 16関節の1スキン。22,688頂点が複数の関節間をブレンド。
- 関節インデックスの範囲、ウェイトの和、逆バインド行列による初期姿勢の復元。
- 5クリップ各53トラック。時刻の昇順、正規化回転、正のスケール。
- 全クリップの先頭と末尾が一致。歩行以外は中立姿勢へ戻る。
  全動作が共通のプロパティを含み、別動作との補間に必要な姿勢を指定。
- 全キーフレームで実際の足メッシュ頂点をワールド座標へ変換し、床の貫通を検出。
  歩行で常に支持脚が残り、左右の遊脚が離床し、ジャンプでは両脚が離床する。
- ウェイト・関節・逆バインド・クリップ欠落・単一ウェイト化・床貫通を故障注入し、
  検証が失敗することを確認。周期歩行の非中立境界は受理し、不一致境界は拒否。

Khronos glTF Validator: エラー0・警告0。
詳細はローカルの `docs/gltf_validation.json`。
`flutter analyze`、Dart/Pythonのフォーマット確認、Webリリースビルドも成功。

接地の数値検証は書き出したキーフレームが対象で、あらゆる中間補間を保証するものではない。
