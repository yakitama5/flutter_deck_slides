## 起動と操作

リポジトリで指定するFlutter 3.47.1 / Dart 3.13.1を使います。
初めて起動するときは、[非公開モデルの復元手順](../../docs/private-assets.md)に沿ってだしゅまるのアセットを準備してください。テストとWebビルドでも同じアセットが必要です。CIではGitHub Secretsを使って自動復元します。

```sh
# リポジトリルート
mise install
flutter pub get
cd slides/20260919_flutterkaigi_mini_lt
flutter run -d chrome
```

`web/index.html`はビルド前のテンプレートなので、ファイルを直接開いても表示できません。ローカルでは上記の起動コマンド、共有時はPRに掲載されるデプロイ済みプレビューURLを使います。

WebはFlutter SceneのWebGL2バックエンドで3Dモデルを描画します。
左右の矢印キーと画面のスライド操作ツールバーで移動でき、各場面に読み上げ原稿と目安の秒数を発表者ノートとして設定しています。

06のデモでは「手を振る」「歩く」「ジャンプ」「待機」のボタンと再生・一時停止を使います。
モデルをドラッグすると視点が回転し、スクロールすると拡大・縮小します。
07以降はスライド送りに合わせて動作と表情が切り替わります。
端末のアニメーション抑制設定が有効な場合、自動の動きを止め、デモボタンによる操作で動かせるようにしています。

- **テーマ**：`MaterialTheme`で生成するMaterial 3の`ColorScheme`を使います。ピンク（シード`#C55883`）を基調に、セカンダリーには青（シード`#438CCA`）のカラーロールを割り当てています。
- **書体**：Kiwi MaruのRegular / Mediumを`assets/fonts/`に同梱しています。

- **図と実例**：バージョン比較、内向きの依存関係、feature firstとlayer firstの配置をFlutterのテキストと図で表現しています。05はFlutter Scene公式の実画像を使用しています。

## 具体例の選び方

### なぜ、責務を層で分けたか

AIが速く生成しても、人が構造を把握して制御しやすくしたいという選定です。
層に分ける設計を入口にし、実際に採用した方式としてオニオンアーキテクチャを明示します。
業務ルールがUIや外部サービスの実装に依存しない関係を説明します。

### なぜ、feature firstにしなかったか

業務では機能をまたぐ処理や責務の変化が多いと考え、層を先に分けるlayer firstを選んだ理由です。
この検索アプリの要件ならfeature firstでも問題ない、という本人のメモも紹介します。
feature firstでも層を設けられるので、層の有無と配置の優先順を混同しません。

設計の二つの判断を紹介したあと、「使ってみたい」も理由になるという話へつなぎます。
